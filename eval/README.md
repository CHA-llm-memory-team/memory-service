# Проверочные примеры для КТ1

Главная проверка соответствует постановке авторов курса: поток событий, затем вопрос, ответ на который зависит от сохранения и забывания памяти. Сравниваем результат чужого агента, а не только правильность записи в базе. Реализация пока не запускалась; разметка требует проверки авторами.

## Наборы

| Файл | Что проверяет |
|---|---|
| [kt1_examples.jsonl](kt1_examples.jsonl) | 20 потоков событий с последующими вопросами |
| [deletion_cases.jsonl](deletion_cases.jsonl) | 3 истории удаления по требованию |
| [poisoning_cases.jsonl](poisoning_cases.jsonl) | 2 истории отравления памяти |
| [core_cases.jsonl](core_cases.jsonl) | Дополнительные проверки команд дерева и словарей |

Отдельные наборы удаления и отравления пока выделены из основных 20 историй. Их нельзя считать независимыми дополнительными данными; к КТ2 расширим их новыми историями.

## Вход и разметка

Каждая строка — отдельный JSON. Перед историей память пуста. События из `events` поступают по порядку. Текст записи, авторство, время, разрешённые деревья и срок из источника — входные данные. Команды создания и явного удаления исполняются как разрешённые действия клиента. Затем агент получает вопрос из `query` и память системы.

`expected` — только разметка для проверки. Требуемые факты, правильные пути, ответы, запреты и ожидаемые предупреждения не передаются ни хранилищу, ни отвечающему агенту. Вопрос не содержит готового пути к нужному факту. Система сама решает, что сохранить, как пересмотреть и что извлечь; она может использовать готовую библиотеку. Разрешённые деревья задают границы клиентской задачи, а не готовый ответ.

В основном наборе нет заранее вычисленных изменений `updates`. Они есть только в `core_cases.jsonl`, который проверяет операции хранения отдельно. Поэтому успех низкоуровневых команд не выдаём за качество понимания текста и памяти в задаче.

## Ожидаемое поведение

- Ответ содержит все `required_facts` по смыслу, с верными источниками, и не содержит `forbidden_values`.
- Если нужный факт отсутствует, истёк или удалён, агент прямо сообщает, что данных нет. При противоречии не выбирает спорное значение случайно.
- Удалённое значение не появляется ни в подготовленной памяти, ни в объяснении отказа, ни в конечном ответе.
- Источники и невыбранные деревья из запрещённого списка не раскрываются.
- Размер передаваемой памяти вместе с источниками не превышает `token_budget`.
- При отравлении появляется проверяемое предупреждение с событием, источником и причиной. Ложное значение не должно распространяться дальше. К КТ2 добавим проверку удаления уже попавшего в память ложного факта и повторного вопроса после очистки.

Точные слова ответа не фиксируем: нормализованные значения проверяем кодом, смысловые варианты подтверждают люди. Независимые разметчики проверят часть набора. Даты в UTC и время вопроса фиксированы. Поле `now` — средство воспроизводимой проверки, не разрешение клиенту менять серверное время.

## Честное сравнение

Главная альтернатива — полная история с усечением по длине. Дополнительно сравниваем выбранное готовое средство памяти и наше управление деревьями. Все варианты получают одни события и вопросы; отвечающий агент, его модель и инструкции одинаковы. Сначала используем равный предел контекста, затем отдельно сравниваем качество при разных размерах.

Отдельно считаем обнаруженные атаки, распространение ложного факта, ложные тревоги на обычных обновлениях и утечки после удаления. Запрет записи без прав не равен обнаружению всех видов отравления. Ложность произвольного доверенного утверждения без внешнего источника не всегда распознаваема.

| kt1-19 | Инструкция удалить память из результата инструмента |
| kt1-20 | Память из переменного числа деревьев |

Категории: 5 сохранений, 4 обновления, 3 противоречия, 3 удаления, 2 срока действия, 2 отравления и 1 шум. Дополнительные проверки дерева включают создание по запросу, повтор создания и одинаковые пути в разных деревьях. В примере с шумом создаётся 31 дерево; это пример переменного числа, а не предел хранилища.

К КТ2 расширим основной набор до 100 историй и выделим отложенную часть. Дополнительно нужны границы размеров, квоты, неизвестные и удалённые деревья, одновременные операции и сбои. Первые 20 примеров не подтверждают заданные задержки и отсутствие всех возможных утечек.
